# Training a Controller on This Dataset

This walks through taking a dataset produced by this repo (or any custom
dataset following the same [output layout](README.md#output-layout)) all the
way through to a trained navigation controller, using
[mast3r-nav](https://github.com/vanshg1729/mast3r-nav) and the
[visualnav-transformer](https://github.com/vanshg1729/visualnav-transformer)
(ViNT/GNM) training code it wraps.

> [!NOTE]
> This document assumes you already have a converted dataset — see the
> [Quick start](README.md#quick-start) in the main README for how to
> generate and convert one with `generate_mass_dataset.py` and
> `postprocess.py`.

---

## 1. Clone mast3r-nav and set up its environment

```bash
git clone https://github.com/vanshg1729/mast3r-nav.git
cd mast3r-nav
```

Follow the setup steps in **mast3r-nav's own README** exactly, in order —
in particular:

- Submodule initialization (`git submodule update --init --recursive`, or
  whatever the repo's README specifies)
- Creating the pixi environment

If you plan to train on your own data (the CARLA dataset from this repo, or
any other custom dataset), you can skip the parts of their README that
download pretrained checkpoints or their own datasets — you won't need
those.

---

## 2. Set up the ViNT/GNM training submodule

Move into the visualnav-transformer submodule:

```bash
cd libs/control/visualnav_transformer
```

There's a README here too — read it and follow its steps for environment
setup exactly.

### 2a. If you want plain GNM/ViNT format (their original format)

Follow their **Data Processing** steps as written. You can skip the data
processing script they mention there — use this repo's
`format_conversion/convert_to_vint_format.py` (or your own script) instead,
as long as the output matches what their training code expects.

### 2b. If you want the modified/mast3r-nav GNM format instead

Ignore their `data_split.py`. After step 2 of their data processing
instructions, your processed data-split should have the following structure
inside `vint_release/train/vint_train/data/data_splits/`:

```
├── <dataset_name>
│   ├── train
|   |   └── traj_names.txt
└── └── test
        └── traj_names.txt
```

#### Custom config files

Use one of the premade YAML files as a starting point and change values as
needed. `config/vint.yaml` is a good choice since it has commented
arguments. `config/defaults.yaml` contains the default config values — don't
train directly with this file, since it doesn't specify any datasets for
training. **Copy `defaults.yaml` into your configs folder as-is, without
changes** — it needs to be present alongside your training config.

#### Custom datasets

Make sure your dataset and data-split directories follow the structures in
the [visualnav-transformer Data Processing section](https://github.com/vanshg1729/visualnav-transformer/tree/43c9b68ba8ab27cb445340fbffc1f370cbe17549#data-processing).

Locate `train/vint_train/data/data_config.yaml` and append:

```yaml
<dataset_name>:
    metric_waypoints_distance: <average_distance_in_meters_between_waypoints_in_the_dataset>
```

Locate your training config file (the one inside the `config/` folder) and
add the following under the `datasets` argument (feel free to change
`end_slack`, `goals_per_obs`, and `negative_mining`):

```yaml
<dataset_name>:
    data_folder: <path_to_the_dataset>
    train: data/data_splits/<dataset_name>/train/
    test: data/data_splits/<dataset_name>/test/
    end_slack: 0 # how many timesteps to cut off from the end of each trajectory (in case many trajectories end in collisions)
    goals_per_obs: 1 # how many goals are sampled per observation
    negative_mining: True # negative mining from the ViNG paper (Shah et al.)
```

Open the config file and **set the correct paths inside it** — specifically
`graphs_path`, `precomputed_filename`, `data_folder`, `train`, and `test`.

See their README for details on resuming training from a previous run that
exited early, if you need that.

---

## 3. Train

From `libs/control/visualnav_transformer` (or wherever `train.py` lives per
their README):

```bash
pixi run python3 train.py --config <path_of_train_config_file>
```

---

## 4. Evaluate on the CARLA dataset from this repo

To run open-loop evaluation of a trained controller against a CARLA dataset
generated by this repo:

1. In the visualnav-transformer config file used to train the controller,
   set `load_run` to point at the checkpoint you want to evaluate.
2. Make sure the mast3r-nav controller config (`configs/carla_waypixel.yaml`
   / `configs/carla_learnt.yaml` from this repo, copied into
   `configs/controller/` inside your mast3r-nav checkout — see the main
   [README](README.md#known-gotchas)) points at the right paths.
3. Run `eval_open_loop.py` from this repo (from the mast3r-nav repo root, or
   with mast3r-nav on your `PYTHONPATH`), with whichever flags are
   appropriate for your setup — see
   [`more_info.md`](more_info.md#eval_open_looppy) for the full flag
   reference.

```bash
python eval_open_loop.py \
    --dataset_root <path_to_converted_mast3r_nav_dataset> \
    --config_path configs/controller \
    --config_name carla_waypixel
```
